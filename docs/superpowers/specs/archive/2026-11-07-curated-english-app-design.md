# 개인 영어 학습 앱 재설계 기획

작성일 2026-11-07. 이전 기획서(https://claude.ai/artifact/QtTP9oy2WzCtictebBS2M3)와 13단계 개발 계획을 대체한다. 표시가 없는 항목은 사용자가 정한 것이고, `제안`은 대화에서 제안해 사용자가 반대하지 않은 것이며, `작성자 판단`은 이 문서를 쓰며 정한 것이다.

## 1. 의도

사용자 한 명이 갤럭시 폰에서 생활회화 어휘를 익히는 앱이다. 수익화는 없다.

이전 기획은 기능이 늘면서 복잡해졌고 말해보카를 너무 따라갔다. 새 기획의 핵심은 **내가 관리하지 않고, 앱이 기억하고 골라준다**이다. 앱을 켜면 오늘 학습 카드 하나만 있고, 나는 앱이 제안한 문제를 풀기만 한다. 앱은 풀이 기록을 계산해 레벨, 학습 속도, 다음 문제를 맞춘다.

## 2. 목표와 범위

**목표**
- 앱을 켜고 바로 학습을 시작할 수 있다.
- 사용자가 복습 대상이나 약점을 직접 관리하지 않아도 앱이 다시 낸다.
- 풀이 기록이 개인화에 쓰이고, 폰을 바꾸거나 저장소가 지워져도 이어진다.
- 학습이 끝나면 내가 늘고 있는지 한 장으로 볼 수 있다.

**만들지 않는 것**
- 대시보드형 홈, 전체 학습 탭, 복습 자료 탭, 하단 메뉴
- 오답노트, 저장한 예문, 학습한 어휘 화면
- 첫 실행 레벨 테스트
- 별도의 기록 화면
- 어휘와 단어를 나누는 탭, 별도의 리스닝 학습
- 말하기 평가, 푸시 알림, 뱃지, 연속 기록, 밀린 개수 강조
- 보기 선택 문제. 빈칸은 항상 직접 입력한다.

**실패로 보는 것**
- 첫 화면에 카드 말고 다른 덩어리가 늘어나는 것
- 기록이 사라져서 개인화가 처음부터 다시 시작되는 것
- 앱이 틀린 영어 문장을 문제로 내는 것
- 말해보카의 문장, 문구, 캐릭터, 외형과 닮는 것

## 3. 제약

- 대상 환경은 안드로이드 갤럭시 폰의 크롬에 설치한 PWA다.
- 사용자는 한 명이다. 회원가입은 없고, 서버 접근은 기존 앱 암호 방식을 쓴다.
- 인터넷이 없어도 문제 풀이는 동작한다. 백업, AI 분석, 문장 물어보기만 멈추고, 연결되면 이어진다.
- Anthropic API 키, Supabase 서버 키, 앱 암호는 서버 환경변수에만 둔다. 코드, 저장소, 브라우저 번들에 넣지 않는다. 값은 사용자가 직접 입력한다.
- 문장은 평범한 구어체와 미국식 철자만 쓴다.
- UI 아이콘은 Lucide만 쓴다. 새 화면은 Taste Skill로 만들고, 완성 후 Impeccable은 검수만 한다.
- 디자인 확정과 사용자의 재개 지시 전에는 개발과 배포를 하지 않는다.

## 4. 사용 흐름

```text
[입구]  오늘의 학습 카드 하나 → 시작
   ↓
[문제]  빈칸 입력, 맞으면 다음 문제
   ↓ 틀리면
[설명]  짧은 설명 → 다음 문제
   ↓ 마지막 문제 후
[오늘 결과] 한 장 → 닫으면 입구
```

## 5. 화면

### 입구

```text
12일째 학습 중이에요                  ⚙

오늘의 학습
카페와 식당  >
10문제 · 약 5분

[시작하기]
```

- 주제를 바꿀 수 있다. 주제는 새 어휘를 가져올 상황이다.
- 문제 수를 5, 10, 15, 20 중에서 바꿀 수 있다.
- 앱이 내 속도에 맞는 추천값을 기본으로 보여준다. 내가 바꾸면 그날만 적용하고, 다음 날은 추천값으로 돌아온다. (`제안`)
- 설정은 오른쪽 위 톱니 아이콘 하나다. (`제안`)
- "며칠째 학습 중"은 학습한 날의 합계다. 쉬어도 0으로 돌아가지 않는다. 연속 일수로 세지 않는다.
- 그날 학습을 끝낸 뒤 다시 열면 같은 입구에서 추가 학습을 시작할 수 있다. 완료를 칭찬하거나 재촉하는 화면은 없다. (`작성자 판단`)

### 문제

- 한글 문장과 뜻 힌트를 보고 영어 문장의 빈칸을 입력한다.
- 삼성 키보드가 한글 상태이면 오답으로 치지 않고 `영어로 써주세요`를 안내한다.
- 힌트 보기를 유지한다.
- 한 문제에 두 번까지 입력할 수 있다. 첫 시도가 틀리면 다시 입력하고, 두 번째도 틀리면 설명으로 간다. (`작성자 판단`, 시도 횟수를 기록하려면 재시도가 있어야 한다)
- 빈칸은 문장당 1개다. 빈칸 하나에 `after class`처럼 여러 단어가 들어갈 수 있다. 빈칸 위치는 자동으로 정하지 않고, 문장을 쓸 때 그 문장에서 배울 표현에 맞춰 정한다.
- 틀린 문제는 그 학습의 맨 끝에 한 번 더 낸다. 같은 표현의 다른 문장을 내고, 다른 문장이 없으면 같은 문장을 낸다. 끝에서도 틀리면 다시 내지 않고 다음 학습의 복습으로 넘긴다. (시점은 사용자 결정, 나머지는 `작성자 판단`)
- 입구의 `10문제`는 처음 푸는 문제 수다. 끝에 다시 내는 문제는 여기에 세지 않는다. 오늘 결과의 정답률도 처음 푼 답으로만 계산한다. (`작성자 판단`)

**빈칸 색 반응**

- 입력하는 동안 답이 맞는 순간 빈칸이 초록색으로 바뀐다. 확인 버튼을 누르지 않아도 된다. (사용자 결정)
- 입력 중에는 틀렸다고 표시하지 않는다. 쓰다 만 글자는 모두 틀린 답처럼 보이기 때문이다. 확인을 눌렀을 때 틀리면 빈칸이 빨간색으로 바뀌고, 그때만 시도 횟수를 센다. (`작성자 판단`)
- 초록색이 되면 정답 문장을 재생하고, 재생이 끝나면 자동으로 다음 문제로 간다. 소리가 나오지 않으면 1초 뒤에 넘어간다. (`작성자 판단`)
- 오타는 입력 중에 판정하지 않고 확인을 눌렀을 때만 판정한다. (`작성자 판단`)
- 한글 입력이 조합 중일 때는 판정하지 않는다.
- 색만으로 구분하지 않고 Lucide 체크와 엑스 아이콘을 같이 쓴다. 초록과 빨강은 빈칸에만 쓴다. (`작성자 판단`)
- 초록색이 될 때까지 여러 답을 넣어보는 것은 막지 않는다. 대신 지운 횟수와 풀이 시간이 숙련도에 반영되어, 이렇게 맞힌 어휘는 더 빨리 복습에 나온다. (`작성자 판단`)

**채점 규칙**

- 문맥에 맞는 형태만 정답이다. 줄임말과 풀어 쓴 말을 자동으로 같다고 보지 않는다. `'d`는 문장에 따라 would도 had도 될 수 있기 때문이다.
- 뜻이 같은 답은 문장마다 정답 목록에 등록한다. 예: `said she'd`와 `said she would`.
- 대소문자는 구분하지 않고, 둥근 따옴표와 곧은 따옴표는 같게 본다.
- 자주 나올 형태 오답은 설명과 함께 문장에 등록하고, 오타 판정보다 먼저 확인한다. 예: `goes` 자리의 `go`, `rest` 자리의 `rests`. 형태 오류로 기록한다.
- 등록되지 않은 답 중 글자 하나만 다른 답은 오타로 본다. 오타는 정답으로 쳐주되 올바른 철자를 보여주고, 숙련도에는 조금 낮게 반영한다.

**듣기 규칙** (`제안`)

| 단계 | 방식 |
|---|---|
| 새 어휘 | 화면이 열릴 때 1번 자동 재생. 다시 듣기 버튼으로 2번 더. 두 번째 재생은 조금 느리게. 남은 횟수를 작게 표시 |
| 복습 | 답을 낼 때까지 듣기 없음. 답을 내면 문장 재생 |
| 틀렸을 때 | 설명 화면에서 정답 문장 다시 듣기 |

소리는 폰의 기기 음성을 쓴다. 복습에서 먼저 듣기를 막는 이유는 정답이 소리로 나오면 떠올리는 연습이 받아쓰기로 바뀌기 때문이다.

### 설명

틀렸을 때만 나온다. 정답, 내가 쓴 답, 뜻 차이 설명, 다시 듣기, `이 문장 물어보기`, 다음 문제만 둔다. 다른 예문과 단어 정보는 뺀다. (`제안`)

`이 문장 물어보기`는 이 화면에만 있고 인터넷이 있을 때만 동작한다.

### 오늘 결과

학습을 마치면 한 장이 나온다. 오늘 푼 문제 수, 정답률, 지난번보다 빨라진 정도, 지금 레벨만 보여준다. 연속 기록 같은 압박 표현은 넣지 않는다. 비교할 지난 기록이 없으면 그 항목은 뺀다. (`제안`)

학습을 중간에 그만두면 푼 문제까지 기록이 남는다. 불이익은 없고, 결과 한 장은 나오지 않는다. (`작성자 판단`)

### 주제 선택

입구의 주제를 누르면 별도 화면으로 넘어간다. 주제 이름만 나열한다. 고른 주제는 다음 학습에도 유지된다. (`작성자 판단`)

### 설정

앱 암호 입력, 소리 속도, 기록 초기화만 둔다. 초기화는 되돌릴 수 없다는 확인을 거친다. (`작성자 판단`)

## 6. 기록

문제 시도마다 저장한다.

- 어휘, 문장, 주제, 시도 시각, 시작 시간대
- 첫 글자까지 걸린 시간, 전체 풀이 시간
- 시도 횟수, 입력한 답, 정답 여부, 오답 유형
- 지운 횟수, 힌트 사용, 듣기 횟수
- 풀이 중 앱을 벗어났는지

학습 한 번마다 시작과 끝 시각, 고른 문제 수와 추천 문제 수, 푼 문제 수, 그만둔 지점을 저장한다.

풀이 중 앱을 벗어나거나 한 문제가 일정 시간을 넘으면 그 시간은 속도 계산에서 뺀다. 기준 시간은 구현에서 정한다.

## 7. 개인화

### 앱이 계산하는 값

- 어휘별 숙련도: 정답 여부, 시도 횟수, 풀이 시간, 힌트 사용을 합친 값
- 나의 망각 속도: 복습 간격을 조정하는 값
- 헷갈리는 짝: 자주 바꿔 쓰는 어휘 쌍
- 오답 유형: 철자 실수, 다른 단어, 시제나 형태 오류
- 주제별 강약
- 학습 속도와 레벨
- 피로 신호: 뒤로 갈수록 느려지거나 틀리는 정도

### 오늘 문제를 고르는 규칙

규칙은 폰에서 돌아서 인터넷 없이 동작한다.

1. 복습 때가 된 어휘를 주제와 상관없이 고른다. 약한 어휘와 헷갈리는 짝을 앞에 둔다.
2. 문제 수의 약 30%는 복습이 많아도 고른 주제의 새 어휘로 남긴다.
3. 새 어휘가 남아 있지 않은 주제는 복습으로 채우고, 입구에서 다른 주제를 고르게 한다. (`작성자 판단`)
4. 복습 간격의 시작값은 1일, 3일, 7일, 14일, 30일이다. 이전 기획의 5분 간격은 학습 끝에 한 번 더 내는 규칙으로 바뀐다. 나의 망각 속도에 따라 간격을 늘이거나 줄인다.
5. 복습할 때마다 같은 표현의 다른 상황 문장을 낸다. 어떤 문장에서 틀려도 그 표현의 숙련도로 계산한다.
6. 2주를 쉬고 돌아와도 밀린 개수를 보여주지 않고 문제 수 안에서만 낸다.

### 처음 시작

레벨 테스트 없이 바로 시작한다. 첫 며칠은 여러 난이도를 섞어 내고, 결과로 레벨을 빠르게 맞춘다. 처음 2~3일은 문제가 쉽거나 어렵게 느껴질 수 있다.

### AI의 역할

- 문제를 매일 고르지 않는다. 그 일은 규칙이 한다.
- 기록이 충분히 쌓이면 분석해서 약점 목록과 학습 방향 조정값을 만든다. 규칙은 이 값을 입력으로 쓴다.
- 첫 버전에서는 AI가 문제 문장을 만들지 않는다. 형식 검사는 영어가 맞는지 가리지 못하고, 앱이 실행 중에 만든 문장은 아무도 보지 않은 채 문제로 나가기 때문이다.
- `이 문장 물어보기`에 답한다.
- 모델은 `claude-opus-5-5`를 기본으로 한다. (`작성자 판단`)
- 분석 주기는 구현에서 정하되, 인터넷이 있을 때 앱을 열면 조건을 확인해 서버에서 실행한다. 비용이 매일 들지 않게 한다. (`작성자 판단`)

## 8. 방식 검토

**문제를 만드는 방식**

| 방식 | 장단점 | 결정 |
|---|---|---|
| 규칙 + AI 분석 | 오프라인 가능, 비용 낮음, 문장 오류 적음 | 선택 |
| 규칙 + AI 분석 + AI 문장 보충 | 재료가 저절로 늘지만 틀린 문장을 막을 수 없음. 별도 AI 검수나 내 승인 화면이 필요함 | 첫 버전에서 제외 |
| AI가 매일 생성 | 가장 맞춤형이지만 인터넷과 매일 비용이 필요하고, 틀린 문장을 알아채기 어려움 | 제외 |

**기록을 저장하는 방식**

| 방식 | 장단점 | 결정 |
|---|---|---|
| 폰 앱 + Supabase 데이터베이스 | 기록을 한 줄씩 쌓아 분석이 쉽고 복구 가능. 서비스 연결 필요, 무료 요금제는 오래 안 쓰면 일시 정지될 수 있음 | 선택 |
| 폰 앱 + 파일 통째 백업 | 구조는 단순하지만 파일이 커지고 분석이 불편 | 제외 |
| 폰에만 저장 | 가장 단순하지만 지워지면 복구 불가 | 제외 |
| 서버에서만 동작 | 오프라인 학습 불가 | 제외 |

## 9. 구조

- 앱은 기존 스택을 유지한다: TypeScript, React, Vite, PWA, Dexie, Vercel Functions, `@anthropic-ai/sdk`.
- 기록은 폰의 IndexedDB에 먼저 저장하고, 보낼 목록에 쌓았다가 인터넷이 있을 때 서버로 보낸다. 같은 기록이 두 번 저장되지 않게 고유 번호를 쓴다.
- 폰은 Supabase에 직접 접속하지 않는다. Vercel 함수가 앱 암호를 확인한 뒤 서버 키로 저장한다. (`작성자 판단`)
- 앱 암호는 설정에서 한 번 입력해 폰에 저장하고, 요청마다 `x-app-passcode` 헤더로 보낸다. 이전 계획의 방식이며, 덕분에 묻지 않고 뒤에서 백업할 수 있다. 값이 맞는지는 서버의 `APP_PASSCODE`로 확인한다.
- 기록은 추가만 한다. 이미 쌓인 기록을 고치지 않으므로 충돌 처리가 필요 없다. 어휘 숙련도 같은 계산값은 기록에서 다시 계산한다. (`작성자 판단`)
- 폰 저장소가 비어 있는 상태에서 앱 암호를 입력하면 서버 기록을 받아 복구한다. 복구할 때는 고유 번호로 합쳐서, 폰에만 있는 기록과 서버에만 있는 기록을 모두 살린다. (`작성자 판단`)
- 기록 초기화는 폰과 서버 양쪽을 지운다. 인터넷이 없으면 초기화를 막는다. 폰만 지워지면 다음 복구 때 기록이 되살아나기 때문이다. (`작성자 판단`)
- AI 분석 결과는 서버에 저장하고 폰으로 내려받아 둔다. 인터넷이 없으면 마지막 결과를 쓴다. (`작성자 판단`)
- Supabase 무료 요금제가 일시 정지되어도 폰에서 학습은 계속되고 기록은 보낼 목록에 남는다. 복구 전까지 백업만 멈춘다. 사용자는 Supabase 화면에서 다시 켠다. (`작성자 판단`)
- 하루는 폰의 현지 시간 자정을 기준으로 나눈다. 학습 일수와 그날만 적용되는 문제 수에 같은 기준을 쓴다. (`작성자 판단`)
- `이 문장 물어보기`는 문장, 내가 쓴 답, 최근 대화 6개만 보낸다. 혼자 쓰는 앱이므로 호출 횟수 제한은 두지 않는다. (`작성자 판단`)
- 저장소에는 Vercel과 Supabase 설정이 아직 없다. 프로젝트 만들기와 키 입력은 사용자가 직접 해야 하므로, 개발 계획에서 서버 연결 단계 앞에 사용자 할 일로 넣는다.
- 문제 문장은 개발 때 쓰고 검토해서 앱 안에 파일로 넣는다. 서버 데이터베이스에는 풀이 기록과 분석 결과만 둔다.

## 10. 문제 재료

- 지금 있는 것은 주제 8개(`content/courses.json`)뿐이고, 어휘와 문장은 아직 없다. 재료 작성은 개발 계획의 한 단계로 넣는다.
- 배우는 단위는 단어와 표현을 합친 어휘다. `rest`도, `after class`나 `said she'd`도 하나의 어휘이고, 기존 `Word.word`에 넣는다.
- 첫 재료는 앞의 주제 3개(인사와 안부, 나와 일상, 카페와 식당)에 주제당 어휘 30개 이상, 어휘당 문장 3개 이상이다. 총 어휘 90개, 문장 270개 이상이다.
- 어휘당 문장 3개는 서로 다른 상황으로 쓴다. 복습 때 다른 문장을 내서 문장 외우기가 되지 않게 한다. 콘텐츠 검사의 최소 문장 수를 2에서 3으로 올린다.
- 새 어휘를 하루 3개쯤 배우면 약 한 달 치다. 떨어지기 전에 같은 방식으로 쓰고 검토해서 다음 주제를 추가한다.
- 난이도는 기존 `Word.level` 1~5를 쓴다. 전체 재료에 1~5가 모두 있어야 첫 며칠 난이도 섞기가 된다.
- 주제 선택 화면에는 재료가 있는 주제만 보여준다. (`작성자 판단`)
- 헷갈리는 짝은 미리 데이터로 만들지 않는다. 내가 입력한 오답이 다른 어휘의 정답과 같을 때 기록에서 찾아낸다. (`작성자 판단`)
- 오답 설명은 기존 `Sentence.notes`를 쓴다.

## 11. 레벨

레벨은 재료의 `Word.level`과 같은 1~5 척도다. 오늘 결과에는 `레벨 2`처럼 정수로 보여주고, 내부 계산은 소수로 해서 어떤 난이도의 새 어휘를 고를지 정한다. (`작성자 판단`)

## 12. 진행 순서

디자인은 아직 확정되지 않았고 개발은 멈춘 상태다. 순서는 시안, 사용자 확정, 개발 계획 다시 쓰기, 사용자의 재개 지시, 개발이다. `docs/archive/design/references/`는 참고 자료일 뿐이고, 시각 방향은 Figma 시안의 검정 바탕과 작은 면적의 노랑을 따른다.

## 13. 기존 작업 처리
